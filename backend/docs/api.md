# REST API

Base URL: `http://127.0.0.1:8000`

All responses include `X-Correlation-ID`. A valid caller-supplied UUID is preserved; otherwise the backend generates one. Use this value when tracing structured logs.

## `GET /health`

Liveness check. This endpoint does not require an OpenAI key or initialized Chroma collection.

```json
{"status":"ok"}
```

Returns `200`.

## `GET /ready`

Readiness check. It verifies the API key, book data file, filter configuration, and Chroma initialization.

Success:

```json
{"status":"ready"}
```

Returns `200` when ready and `503` otherwise:

```json
{"detail":"The application is not ready."}
```

Readiness errors intentionally do not expose filesystem paths, provider details, or tracebacks.

## `POST /chat`

Returns a recommendation and the complete local summary selected through the summary tool.

Request:

```json
{
  "question": "I want a science-fiction book about politics",
  "history": [
    {"role": "user", "content": "I enjoyed complex world-building."}
  ]
}
```

`question` is required, trimmed, and limited to 500 characters. `history` defaults to an empty array and is limited to 20 messages. Unknown fields are rejected. Message roles and content are validated by the domain model.

Success:

```json
{
  "recommendation": {
    "title": "Dune",
    "author": "Frank Herbert",
    "rationale": "It matches the request."
  },
  "summary": "Complete local book summary."
}
```

Returns `200`.

## Error Contracts

Validation errors generated by FastAPI return `422` with a `detail` array. Filter validation and rejected content return `400` with a stable `detail` string. Missing local books return `404`. Provider, retrieval, tool, catalogue, and filter-configuration failures return `502`:

```json
{"detail":"The recommendation service is temporarily unavailable."}
```

Requests over the configured body limit return `413`:

```json
{"detail":"Request body exceeds the maximum allowed size."}
```

Internal exception text, secrets, prompts, completions, summaries, tool arguments, and filesystem paths are not returned by error responses.

## CORS

CORS origins are configured through `CORS_ALLOWED_ORIGINS`. Origins must be explicit; wildcard `*` is rejected by settings validation. The default development origins are `http://localhost:5173` and `http://localhost:3000`.
